open-rig

A viewer for open-tick traces. Everything runs in your browser; no file leaves your computer.

Examples:

Plots

Wheel to zoom, drag to pan, double-click to reset. With the plots focused, use the arrow keys and + or −.

Acceptance criteria

Each window is shaded green if the criterion passed and red if it failed. ▼ marks the event a reaction is timed from, ● where the reaction ended, ✕ the first violation. Choose a criterion to zoom to its window and draw it over the plots.

    A against B

    B is read at A's times, with linear interpolation, where B has a value. Only columns that both traces have are compared.

    What this reads

    The CSV that open-tick writes: a header of column names, then one row per step, with no quotes. An empty cell is a gap. See the trace format. Without a layout, number columns are grouped by the unit their name ends in (_rpm, _nm, _pct, _bar, _kpa, _c), and text columns and 0/1 columns are drawn as state strips.

    A frame log, written by open-tick (--frames in open-crank's runners), has every CAN frame of the run with two times: t_s, the step in which it crossed the simulated machine's side, which places it on the axis, and t_bus_s, when it was on the bus, measured by the clock the file names. See the frame log format. With a DBC file, each frame is named and its signals decoded; when the DBC says ProtocolType "J1939", frames are matched by PGN, BAM transfers are reassembled, DM1 lamps and trouble codes are read, and each TSC1's counter and checksum are checked. open-crank's dictionary is open-crank.dbc.

    A verdict file, written by open-tick's acceptance oracle, says for each criterion whether it passed, its time window, the event a reaction is timed from, where the reaction ended and where the criterion first failed. See the verdict format.
